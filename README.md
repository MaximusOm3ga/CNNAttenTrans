# Learning Patch-Level Temporal Representations for Transformer-Based Time-Series Forecasting

This repository contains the experimental code used for a patch-based forecasting study in which a CNN token encoder is first trained to summarize temporal patches, and a transformer model is then trained on the resulting patch-token sequence for forecasting.

The project includes:

- synthetic benchmark generation for controlled evaluation
- a proposed two-stage architecture
- baseline comparisons using TCN and PatchTST
- an electricity-load real-data evaluation pipeline using the ElecDS benchmark

The repository is structured as an academic reproduction / study codebase rather than a production forecasting package.

## 1. Study summary

The proposed method follows a two-stage design:

1. Patch tokenization with a CNN encoder trained to reconstruct patch-level temporal structure.
2. Forecasting on the token sequence with a transformer head (QuantFormer).

The code compares this approach against patch-aware baseline models, including:

- TCN
- PatchTST

The benchmark scripts evaluate both synthetic and real datasets.

## 2. Data conventions

The datasets are stored as PyTorch dictionaries and follow the repo’s time-series convention:

- `X`: shape `(N, T, F)`
- `Y`: shape `(N, T)`

For patch-level evaluation, the target is reduced over each patch using the mean value across the patch unless a script explicitly states otherwise.

## 5. Synthetic dataset experiment

The synthetic benchmark is generated by `Paper/dataset/data.py`.

From the repo root:

```powershell

```

This creates the synthetic dataset file used by the proposed pipeline and baseline scripts.

### 5.1 Proposed pipeline (full synthetic run)

The end-to-end proposed workflow is:

```powershell
cd .\Paper\proposed
python .\run_pipeline.py
```

The orchestrator runs the following sequence automatically:

1. `Paper/proposed/modelCNN/training.py`
2. `Paper/proposed/modelCNN/token_ex.py`
3. `Paper/proposed/transformerModel/training.py`
4. `Paper/proposed/transformerModel/eval_unseen.py`

### 5.2 Run the proposed pipeline step-by-step

From the script directories:

```powershell
cd .\Paper\proposed\modelCNN
python .\training.py
python .\token_ex.py

cd ..\transformerModel
python .\training.py
python .\eval_unseen.py
```

## 8. Synthetic long-horizon evaluation

The long-horizon runner trains all three forecasting models on `paper_dataset.pt` and evaluates them only on `paper_new_test.pt`. It evaluates patch horizons `h=3` and `h=5`, corresponding to 24 and 40 timesteps with the repository's patch size of 8. The pretrained CNN encoder is reused; only the forecasting models are retrained for each horizon.

From the repository root:

```powershell
python .\Paper\synthetic_long_horizon\evaluate_long_horizons.py
```

The default is 300 epochs per model and horizon. To run a smoke test or select a horizon:

```powershell
python .\Paper\synthetic_long_horizon\evaluate_long_horizons.py --epochs 1 --horizons 3
python .\Paper\synthetic_long_horizon\evaluate_long_horizons.py --epochs 300 --horizons 3 5 --batch-size 32
```

The final output reports MSE, MAE, and RMSE for QuantFormer, TCN, and PatchTST separately at both horizons.

## 9. Synthetic encoder-component ablation

The faithful synthetic ablation evaluates the contribution of dense connections, attention-weighted pooling, and reconstruction-time token self-attention. Each variant follows the proposed two-stage schedule: encoder autoencoder pretraining for 2,000 epochs, followed by QuantFormer training for 300 epochs with best-validation checkpoint selection. The final test set is `Paper/dataset/paper_new_test.pt`.

```powershell
python .\Paper\ablation\synthetic\synthetic_encoder_ablation.py --runs 5
```

For a short smoke test:

```powershell
python .\Paper\ablation\synthetic\synthetic_encoder_ablation.py --runs 1 --encoder-epochs 1 --transformer-epochs 1
```

The script reports per-run and aggregate mean +/- standard deviation for MSE, MAE, and RMSE.

## 11. Notes

- Most scripts use relative file paths and are designed to be launched from their containing folder.
- Patch size is an important experimental invariant throughout the repository and should remain consistent across tokenization, transformer training, and evaluation.
- The codebase is intended for academic benchmarking and methodological comparison rather than deployment-level forecasting software.
- If import errors appear, run the script from the folder that contains it, or ensure that the repository root is on `PYTHONPATH`.
